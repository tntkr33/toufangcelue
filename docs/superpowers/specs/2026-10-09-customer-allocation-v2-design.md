# v2.0 客户投放查询设计

日期：2026-10-09

状态：功能方案已确认；用户已要求直接完成 v2.0，无需等待逐项审批。

## 1. 目标与范围

在现有本地工具中新增“客户投放查询”页签。上传客户基本信息表后，将当前已解析、已应用人工修改的品规投放数量匹配到客户，重点提供全市及筛选范围内的品规投放总量，并可查看客户明细和导出查询结果。

这是策略测算的投放量，不是客户实际订货量或销售量。继续使用现有 Python 本地服务，不增加 Web 框架，不上传业务数据至外部服务，不改变原有策略解析、维度模板、隐藏系统标识及系统导入 XLS 的生成算法。

本期不按订货周期、周次或周几排除客户，也不实现周期规则、历史报表管理、客户基础数据编辑或实际订单对账。

## 2. 已确认的业务口径

- 客户来源为用户上传的客户表，全表客户均进入校验，不按订货安排排除。
- 按当前模板所需维度和客户档位匹配最终投放数量；人工修改必须先应用，未应用的草稿不参与计算。
- 用户所称业态是“城市、县城、乡镇、农村”，使用客户表“市场类型(扩展)”，不是“业态(国标)”。
- 已确认“不导出”的品规默认不参与测算和汇总。
- 数量同时展示条和箱，1 箱 = 250 条。条数为计算基准，先汇总条数再换算箱数，箱数显示至三位小数，避免累计舍入差。
- 页面提供“品规汇总”和“客户明细”两个视图，默认品规汇总。
- 导出当前视图、当前筛选条件下的全部匹配结果，不仅是当前分页。
- 无法匹配的客户或客户与品规组合单独列出原因，不按 0 条冒充匹配成功；汇总存在缺项时明确标识。

## 3. 客户表读取与校验

按表头识别字段，允许标题行在表头之前，不依赖固定列号。全空行跳过；非空行缺少关键字段必须报告，不能静默丢弃。

保留客户编码、客户名称、营销部、档位、市场类型(扩展)，商圈模板另读取“商圈类型(扩展)”。客户编码和商品编码以文本处理，保留前导零。负责人、许可证号、客户经理等无关字段不进入报表或日志。

客户编码作为去重依据：相同编码且测算字段一致的重复行合并为一个客户并提示重复来源行；相同编码但匹配字段冲突时，该编码列入异常，不任取一条或重复计算。无客户编码的非空行列入异常。

档位只接受可明确解析的 1 至 30 档。营销部、市场类型、商圈名称采用受控规范化与显式别名映射；不使用模糊相似度猜测归属。需要的字段不存在时阻止该模板的测算，并提示补充列；单行缺失或未知值列入异常。

具体匹配维度随已选模板变化：

| 模板 | 匹配字段 |
| --- | --- |
| 档位+区县 | 营销部、档位 |
| 档位+区县+市场类型 | 营销部、市场类型(扩展)、档位 |
| 档位+区县+商圈 | 营销部、商圈类型(扩展)、档位 |
| 档位+市场类型 | 市场类型(扩展)、档位 |

查询筛选仍可使用客户自身的营销部和市场类型，不因模板缺少某维度而放弃客户信息。商圈的对应关系必须通过本地模板校验，不能把国标商圈自动当作扩展商圈。

## 4. 品规范围与数据版本

当前 v1.9 的导出选择仅用于当次导出请求，尚未持久保存在会话中。v2.0 需要将“已确认品规范围”作为同一解析会话内的共享状态，而不是推测上一次导出的内容。

查询前复用现有品规确认清单；没有已确认范围时，使用当前建议默认值展示清单并要求确认。用户无需先生成系统 XLS 才能查询。确认后查询和系统导出使用同一份选择；取消清单不改变已确认状态。系统导出仍保留确认步骤，展示当前选择。

策略重解析、模板变化、应用文字或数量修改会使旧品规确认和旧测算失效。客户表替换或确认品规范围变化会使旧测算失效。页面提示重新测算，旧结果不允许导出。

每份测算结果绑定策略版本、客户数据版本、品规范围版本。查询结果再绑定筛选条件与视图；导出必须使用页面显示结果对应的版本和条件。筛选条件编辑后尚未查询时，禁用旧结果导出，不能将未生效的筛选应用到后台导出。

## 5. 计算与汇总

每个有效客户、每个参与测算的品规最多匹配一个最终维度数量。使用当前 reviewRows 中的 assignments，不再次解析原文或绕开人工覆盖。

维度匹配成功且数量为 0 是有效零投放，纳入匹配客户数和明细；缺失、冲突、多个候选维度或无对应维度则是未匹配，不记作 0。对无明确数量规则但被用户保留导出的品规，沿用现有最终数量，并保留原校验提示，不将解析结果包装成实际订单。

同商品编码出现无法唯一解释的多条品规策略时报告冲突，不重复叠加为客户投放量。

品规汇总按品规输出匹配客户数、非零投放客户数、未匹配客户数、测算投放量(条)、测算投放量(箱)。客户明细按“品规 + 客户”一行输出。

顶部客户数使用唯一客户数，不能把客户与多个品规的组合行数当作客户数。汇总总量等于同条件下所有成功匹配明细的条数之和；任何未匹配情况均显示“存在缺项”，不能显示为完整全市总量。

## 6. 查询页面

与原策略页共享会话，通过页签切换，不要求重复上传策略。客户表上传区显示文件名、有效客户数及异常数。

筛选条件：品规搜索及多选、营销部/区县多选、起止档位、市场类型多选；档位边界包含端点。默认所有参与测算品规、全部区县、1 至 30 档、全部市场类型。显式取消全部选择表示空结果，不暗中还原为全选。

表格提供分页和结果数量。品规汇总与客户明细使用一致的筛选条件；切换视图不改变筛选范围。另提供“未匹配清单”入口，显示客户编码、客户名称、原表行号、相关维度、受影响品规及原因。

原策略校验提示继续保留。针对数据缺失、无结果、会话失效、正在测算、导出进行中和失败提供明确状态，不静默显示空白或沿用旧数字。

## 7. 统计 Excel 导出

统计导出采用 .xlsx，与系统导入用的 .xls 分开命名和操作，不写入系统隐藏标识。

品规汇总列：商品编码、商品名称、匹配客户数、非零投放客户数、未匹配客户数、测算投放量(条)、测算投放量(箱)。

客户明细列：商品编码、商品名称、客户编码、客户名称、营销部、档位、市场类型(扩展)、测算投放量(条)、测算投放量(箱)；使用商圈模板时增加匹配商圈列，页面与 Excel 同步增加。

表头说明记录当前筛选条件、计算单位和缺项状态；不额外导出未被筛选中的业务行，也不将另一个视图的明细偷偷附加到导出文件中。未匹配清单提供单独的导出操作。

超过 XLSX 单工作表容量时自动续接下一张同结构工作表，不截断结果。显示分表数量与导出进度。继续沿用系统另存为、打开文件和打开所在位置交互，扩展其 XLSX 支持，但不能绕过现有本地文件操作授权与成功保存校验。

## 8. 实现边界与性能

新增独立客户读取/规范化模块、匹配与查询模块、统计 XLSX 导出模块及查询 UI 模块。server.py 只增加会话衔接、输入校验和接口路由；复用现有样式、确认清单、本地文件操作与退出保护。

客户规模约两万、品规规模约两百，明细组合可达数百万行。按客户维度分组建立索引，汇总通过分组计数与品规最终数量计算；明细按需分页生成。不能将所有组合送入浏览器或一次性构建全部单元格对象。导出分批/流式生成，超出工作表容量自动分表，失败清理临时文件，不给用户半成品。

上传、测算与导出期间阻止退出中断；导出期间冻结对应数据版本。后端校验请求参数和结果版本，不仅依赖前端按钮禁用。保留关闭最后一个页面后延时退出的行为；内存会话关闭后不保留未导出修改。

本期不引入数据库。实际客户表、私有模板、测算数据、报表及包含业务数据的缓存均不进入 Git；测试使用合成数据。

## 9. 验收

1. 人工构造客户与策略，验证 4 种模板匹配、零数量、范围端点、条箱换算及人工修改覆盖。
2. 验证“不导出”品规不参与任何统计，品规范围无需先导出系统 XLS 即可确认。
3. 验证重复客户、冲突客户、缺字段、未知维度、异常档位、重复品规策略不会静默漏计或重复计数。
4. 验证原始策略/客户/排除清单更新后旧统计和旧导出失效。
5. 相同条件下逐行核对页面结果与 XLSX，核对所有分页、所有分表及明细合计与汇总合计相等。
6. 使用约两万客户、约两百品规的合成数据检查分页、汇总、批量导出和多表容量边界，浏览器不加载全量明细。
7. 回归 v1.9 的多选、策略编辑、品规清单、4 种系统 XLS 模板隐藏标识、日期表头、保存打开及退出保护。
